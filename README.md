# D2Turbo app (macOS + Windows beta)

> This repository is published from `app/` of a larger checkout (`npm run push:app`). The engine (`Minify/`, the bundled mods) and the build scripts (`scripts/`) are not included, so it does not build on its own. Paths such as `../scripts/…` refer to that checkout.

A Tauri 2 shell over the Minify engine. Its one screen has a dependency checklist, **Patch** and **Uninstall** buttons, a progress view and the build version. Patch applies a fixed mod set: `#base`, `#English Fix`, `D2Turbo` and `OpenDotaGuides Guides`.

## How it works

- `src-tauri/binaries/d2turbo-engine-<triple>` is the headless Minify CLI built by PyInstaller ([scripts/D2TurboEngine.spec](../scripts/D2TurboEngine.spec)). It ships without the webview UI, plugins or themes.
- The engine's home is `~/Library/Application Support/com.d2turbo.app/engine` on macOS and `%APPDATA%\com.d2turbo.app\engine` on Windows. It holds `mods/` (synced from the bundle on every new build), `config/`, `cache/`, `logs/` and `backup/`.
- The engine runs with `MINIFY_HOME`, `MINIFY_EVENTS=json` and `MINIFY_NONINTERACTIVE=1`. It writes one JSON event per line to stdout, and the app forwards each one as an `engine://event` event. A finished task is reported as `engine://done`.
- Before every run, `config/mods.json` is rewritten so that only the preset mods are enabled.

## Logs and bug reports

- **App log**: `~/Library/Logs/com.d2turbo.app/D2Turbo.log` on macOS, `%LOCALAPPDATA%\com.d2turbo.app\logs\D2Turbo.log` on Windows. It rotates at 5 MB and keeps 3 files. It records the app version, every status check, task start and finish, every engine line, UI errors (`log_ui`) and Rust panics. The engine's own `logs/` folder is cleared at the start of each patch, so this file is the only history.
- **"Поделиться логом с разработчиком"** (footer link, plus a button under a failed Patch/Uninstall) runs `send_report` ([src-tauri/src/report.rs](src-tauri/src/report.rs)). It builds `<id>.zip` with these files:
  - `meta.json`: report id, version, build, OS and arch, comment, contact, the last result and the last status;
  - `app/*.log`: the 3 newest app logs;
  - `engine/logs/*`;
  - `engine/config/{minify_config,mods}.json`;
  - `dota/console_d2turbo.log`: the `[D2Turbo]` lines from Dota's `console.log`.

  Each file is cut to its last 3 MB, and the user's home path is replaced with `~`. The zip is saved to `<log dir>/reports/` (the last 5 are kept) and then uploaded. If the upload fails, the UI offers to reveal the file so it can be sent by hand.
- **Endpoint**: `REPORT_URL`. Override it at build time with `D2TURBO_REPORT_URL=https://… npm run tauri build`. Request format: `POST` `multipart/form-data` with the fields `meta` (the JSON from `meta.json`) and `logs` (`<id>.zip`, `application/zip`), and `User-Agent: D2Turbo/<ver> (<os>)`. Any 2xx response counts as delivered. The id (`XXXX-XXXX`) is generated by the client and shown to the user, so they can quote it.

## Development

Requirements: Rust (rustup), Node, uv.

```sh
npm install
npm run build:engine     # rebuild the sidecar after any change in Minify/
npm run tauri dev
npm run tauri build      # → src-tauri/target/release/bundle/dmg/D2Turbo_<ver>_aarch64.dmg
```

Tests: `cargo test` in `src-tauri`, and `uv run pytest` in the repo root.

## Release builds (both platforms)

On an Apple Silicon Mac:

```sh
npm run build:launchers                 # → builds/D2Turbo_<ver>_aarch64.dmg + builds/D2Turbo_<ver>_x64-portable.zip
npm run build:launchers -- --only windows   # or --only mac
```

[scripts/build_launchers.py](../scripts/build_launchers.py) rebuilds both engines and both apps. The Windows build is a cross-build:

- **Engine.** Windows CPython (the NuGet `python` package) runs PyInstaller under Wine. The host's `uv` installs the Windows wheels, so pip never runs inside Wine. Everything is cached in `build/win-toolchain/`, which includes a dedicated Wine prefix so that `~/.wine` is left untouched.
- **App.** `tauri build --runner cargo-xwin --target x86_64-pc-windows-msvc --no-bundle` builds the exe. `cargo-xwin` downloads the MSVC CRT and Windows SDK on first use, and `llvm-rc` (`brew install llvm`) embeds the icon and manifest.
- **Portable zip.** It contains `D2Turbo.exe`, `README.txt`, `mods/` and `engine/` (`d2turbo-engine.exe` with its `_internal/` folder), so `D2Turbo.exe` is the only exe users see at the top level. On Windows the engine is a PyInstaller *onedir* build with a VERSIONINFO resource: a onefile exe unpacks itself into `%TEMP%` on every run, and AV heuristics flag that as a dropper/injector. On Windows, Tauri looks for the resources next to the exe, and the sidecar is resolved as `engine/d2turbo-engine.exe` (`SIDECAR` in `engine.rs`). The app needs the WebView2 Runtime, which Windows 10/11 already ship with.

### Publishing to GitHub Releases

```sh
npm run release                          # build both and publish release v<version>
npm run release -- --only windows        # rebuild one platform and replace its asset
npm run release -- --notes "What changed"
```

The target repo comes from `RELEASE_REPO` in [scripts/build_launchers.py](../scripts/build_launchers.py), or from `D2TURBO_RELEASE_REPO` or `--repo owner/name`. Publishing needs `gh` (`brew install gh && gh auth login`). The tag is `v` + the version from `tauri.conf.json`. If the release already exists, its assets are replaced. To ship a new version, bump the version in `tauri.conf.json`, `Cargo.toml` and `package.json` first.

Assets have stable names, so a site can always link the newest build:

- `https://github.com/<repo>/releases/latest/download/D2Turbo-macos-arm64.dmg`
- `https://github.com/<repo>/releases/latest/download/D2Turbo-windows-x64.zip`

Releases are not marked as prerelease, because `/releases/latest` skips prereleases. The repo must be public.

The script requires Wine (`~/.local/bin/wine`), uv, Node, rustup and Homebrew LLVM. It installs the Rust Windows target and `cargo-xwin` itself.

On Windows the app has no dependency checks. `resourcecompiler.exe` runs natively once the *Dota 2 Workshop Tools DLC* is installed in Steam.

## Installing the beta

The build is ad-hoc signed and not notarized. The first time you open it, right-click the app and choose **Open**. If macOS still blocks it, run `xattr -cr /Applications/D2Turbo.app`.

The CSS/XML part of D2Turbo (hero tiers, league rating) needs Rosetta 2, Wine, DXVK-macOS and the Dota 2 Workshop Tools (`rescomproot`). The checklist in the app explains how to install each one. Without them, Patch still installs the guides and the custom guide name.
